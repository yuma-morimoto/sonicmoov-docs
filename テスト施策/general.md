## 2つの目標
テスト施策にはテストの標準化と浸透の目標と、テスト導入効果という2つの目標がある。主にテスト導入効果がROIの指標となる。

## ゴール設計・やること
以下の数値目標はテストありなしで比較する（AIを使うかどうかは関係ない）

1. ~~**スキル導入後、テスト実装の70%以上でテストスキルが活用された**~~ → 計測の仕方が難しいのでやめる
	- 対象案件でスキルの参照ログをとる
2. **評価期間中に稼働している案件のガイドライン導入率25%以上**
	- skillsリポジトリに集約するのでほぼ達成見込み
3. **実装・修正の心理的負荷の削減を5段階評価で4以上を獲得**
	- テストがあることによる心理的負荷の軽減アンケートとる
4. **バグ修正対応工数を30%削減**
	- 方法：BeforeとAfterを比較する
		- Before - 過去のテストなしプロジェクトにおける実際のバグ対応チケット（バグ解消PR、対応工数）
		- After - Beforeにおいてskillsでテストを書き（この時AIにバグ情報を伝えない）、テストを活用してバグ対応させる
5. **動作確認工数を30%削減**
	- 方法：削減率 ＝ 自動化できた項目数 ÷ 全項目数

## 工数
- 体系化工数：270,000円（60h）（MTGや調査、検証）
	- 第1回MTG：0.5h * 4人 = 2h
	- 現状把握：5案件 * 4h = 20h
	- 第2回MTG：0.5h * 4人 = 2h

- 標準化工数：180,000円（40h）（MTGや資料作成）

- パイロット検証のマイルストーン設計は案件のスケジュール都合により、予測ができないため厳密な設定ができない。そのためマイルストーンの達成基準を進捗率にする段階的検証を取り入れる。
- 8月以降の導入案件の目安は3案件（1案件でテスト分析から運用改善まで回すのが理想）
- 網羅マトリクス
	- テスト分析 × 案件A / B / C
	- テスト実装 × 案件A / B / C
	- 運用・改善 × 案件A / B / C
