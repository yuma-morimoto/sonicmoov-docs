
## 改善前
```tsx
it('1,000 は右寄せの等幅数字で単位「円」が付くこと', async () => {
    await renderTable();

    const cell = valueCells()[0];
    const unit = document.querySelectorAll('.drk-amt-unit')[0] as HTMLElement;
    expect(cell.textContent).toBe('1,000');
    expect(getComputedStyle(cell).textAlign).toBe('right');
    expect(getComputedStyle(cell).fontVariantNumeric).toContain('tabular-nums');
    expect(unit.textContent).toBe('円');
  });
```

問題点：
1. **CSSクラスに依存していた**: `.drk-amt-unit` で要素を取得しており、クラス名を変えるだけで壊れる。
2. **数字と単位の対応を保証していなかった**: セルと単位をインデックス `[0]` で別々に取っていたため、同じ行の組み合わせかどうかを検証できていない。
3. **内部のDOM構造を前提にしていた**: 数字と単位が別要素であることを前提にしており、ユーザーに見える「1,000円」というまとまりを見ていない。
4. **CSSの値を検証していた**: `textAlign` や `fontVariantNumeric` の値を見ているため、見た目が同じでも実装を変えると落ちる。
5. **jsdomでは結果が信頼できない可能性があった**: jsdom は `getComputedStyle` でスタイルを正しく計算しないため、テストの結果自体があてにならない。
6. **1テストで検証することが多すぎた**: 書式・配置・フォント・単位を1ケースにまとめていたため、落ちたときに原因が特定しにくい。
7. **レイヤーの役割が重複していた**: 桁区切りの書式は単体テスト、右寄せや桁揃えはVRTの役割で、コンポーネントテストで担保する内容ではない。

## 改善後

```tsx
it('金額が1000円の行では、金額欄に「1,000円」と表示される', async () => {
  await renderTable();

  const row = screen.getByRole('row', { name: /商品A/ }); // 対象行を行の内容で特定
  expect(within(row).getByRole('cell', { name: '1,000円' })).toBeInTheDocument();
});
```
