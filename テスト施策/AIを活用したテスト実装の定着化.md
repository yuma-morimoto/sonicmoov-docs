## 施策内容：具体的な実行計画
- 施策の全体像:
	- **Ph0. 立ち上げ・引き継ぎ**
	    - 前施策を成果と未完了事項を整理したうえでクローズし、新施策で使う資産（SKILL・ガイドライン）を確定する
	- **Ph1. 計測基盤の整備・ベースライン取得**
	    - カバレッジとAI記述率を「誰でも同じ方法で」測れる状態にし、施策開始時点の数値を取る
	- **Ph2. 進行案件への展開**
	    - 施策期間中の進行案件にSKILLを導入し、AIでテストを書くことを標準の開発フローに組み込む
	- **Ph3. 定着・改善サイクル**
	    - 月次で数値を確認し、カバレッジ不足やAIが書けなかった箇所をSKILLの改善にフィードバックする
	- **Ph4. 評価**
	    - 中間評価と1年後の最終評価で、カバレッジ達成状況・AI記述率・削減工数（ROI）を確定する

- **実行手順（詳細）:**
    - **Ph0. 立ち上げ・引き継ぎ（〜2026/11末）**
        - 前施策のクローズ
            - 成果（ガイドライン → SKILL化、パイロット案件での導入実績、ヒアリング結果）を1枚にまとめて報告する
            - 未完了事項（バグ修正・動作確認工数30%削減の客観評価、E2E/シナリオテストのルール化 等）は「新施策で扱う / 扱わない」を判断する
        - 引き継ぐ資産の確定
            - frontend-testing SKILL（test-plan / test-gen）をskillsリポジトリの正式版として固定する
            - ガイドラインは人が読む参照資料として残し、更新はSKILL側を正とする
        - 体制・役割の再確認
            - 責任者・担当者、案件側の協力者（各案件1名）を決める
    - **Ph1. 計測基盤の整備・ベースライン取得（2026/12）**
        - カバレッジ計測の共通化
            - 計測指標を決める（例：Lines カバレッジ、対象はロジックを持つファイル）
            - 計測対象外（ロジックを持たない静的コンポーネント、型定義、設定ファイル、生成コード等）を共通の除外設定として定義し、skillsリポジトリで配布する
            - Astro/マークアップ案件は `.astro` が計測しにくいため、scripts配下のみを対象とするなど案件種別ごとの扱いを決める
            - CIでカバレッジを自動出力する（codecov 等の導入可否を判断）
        - AI記述率の自己申告方法を決める
            - PRテンプレートに「このPRのテストコードのうちAIが書いた割合」（0 / 25 / 50 / 75 / 90 / 100%）の選択欄を追加する
            - あわせて「AI出力をどの程度手直ししたか」（ほぼそのまま / 一部修正 / 大幅修正）を任意で記入してもらい、削減工数の補正に使う
            - 集計は案件ごとに月次で行う
        - ベースライン取得
            - 施策開始時点の進行案件のカバレッジとテスト有無を記録する
            - テスト実装工数の基準値を決める（例：実装見積工数 × 係数0.2 をテスト実装工数とみなす）
    - **Ph2. 進行案件への展開（2027/1〜2027/3）**
        - 対象案件の選定
            - 施策期間中の進行案件を一覧化し、母数を確定する（終盤の案件・テスト対象がない案件は対象外）
        - 開発フローへの組み込み
            - 設計・画面確定後に test-plan でテスト計画を作り、Git管理する
            - 実装時に test-gen でテストを生成し、レビューではテスト計画を見て観点の漏れを確認する
            - バグ修正時は Red-Green-Refactor の手順でテストを追加する
        - 導入支援
            - 案件キックオフ時にSKILLの使い方を説明する（モブプロ形式・30分程度）
            - 導入手順・よくある質問をREADMEにまとめ、案件メンバーが自走できるようにする
    - **Ph3. 定着・改善サイクル（2027/4〜2027/9、月次）**
        - 月次レビュー（30分）
            - 案件別のカバレッジとAI記述率を確認する
            - 75%未達の案件は、不足している箇所とその理由（AIが書けない / 工数がない / 書き方がわからない）を確認する
        - SKILLの改善
            - AI記述率が低い箇所・AIの出力を大幅修正した箇所を集め、SKILLのルールや参照ファイルに反映する
            - 改善内容はskillsリポジトリのリリースノートとして共有する
        - 標準化
            - 定着した運用（テスト計画のGit管理、PRテンプレート、カバレッジ除外設定）を全案件の標準とする
            - 必要に応じて見積テンプレートにテスト実装工数を明記する
    - **Ph4. 評価**
        - 中間評価（2027/4）
            - カバレッジ75%達成案件の割合、AI記述率の平均を確認し、目標と進め方を見直す
        - 最終評価（2027/10〜11）
            - カバレッジ：施策期間中の進行案件ごとの達成状況
            - AI記述率：自己申告の平均値（テスト実装工数で加重）
            - ROI：テスト実装削減工数 = Σ（案件のテスト実装工数 × AI記述率 × 手直し補正）を金額換算し、施策投資と比較する
- **成果物:**
    - frontend-testing SKILL（正式版・改善版）
    - カバレッジ共通除外設定 / CI設定
    - AI記述率申告欄を含むPRテンプレート
    - 月次レポート（案件別カバレッジ・AI記述率）
    - 最終評価レポート（ROI算出）
