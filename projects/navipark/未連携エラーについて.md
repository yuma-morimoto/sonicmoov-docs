バックエンドエンジニア向けには、以下の流れです。

```text
1. アプリ起動
   ↓
2. 認証情報を使って GET /api/member を実行
   ↓
3. バックエンドが以下を返す
   HTTP status: 401
   body.code: 403
   message: ユーザーが連携されていません。
   ↓
4. フロントの useNaviparkApiClient は、
   code: 401 の場合のみトークン更新・再試行・サインアウトを行う。
   code: 403 はその分岐に入らず、エラーとして返却する。
   ↓
5. 02.auth.global.ts で memberInfo.value が null の状態になる
   ↓
6. 以下の処理で null 参照エラーが発生
   memberInfo.value.accountType
   ↓
7. エラー画面を表示
   500: null is not an object (evaluating 'ae.value.accountType')
   ↓
8. ユーザーがエラー画面の「HOMEへ戻る」を押下
   ↓
9. clearError({ redirect: '/' }) でトップページへ遷移
   ↓
10. トップページのURLに検索クエリがないため、
    parkingType が undefined の状態で検索コンポーネントを初期化
   ↓
11. ListsByLocation.vue で以下を実行
    props.parkingType.toUpperCase()
   ↓
12. 二次エラーが発生
    500: Cannot read properties of undefined (reading 'toUpperCase')
```

Sentryでも、次の順序が確認されています。

```text
/api/member → 401（body.code: 403）
→ accountType参照エラー
→ closeSplash
→ 「HOMEへ戻る」クリック
→ parkingType.toUpperCaseエラー
```

今回の再現では、QRコードや`parkingType`付きURLを使わなくても同じ挙動になりました。したがって、バックエンド側にはまず、**どの条件で認証済みユーザーに対して「ユーザーが連携されていません」（HTTP 401 / code 403）を返すのか**を確認したいです。

確認対象は、Cognitoユーザーとナビパーク会員の連携レコード、`User-Id`・`Member-Token`・Cognitoユーザーの対応関係、連携解除・退会・トークン更新時の状態遷移です。
