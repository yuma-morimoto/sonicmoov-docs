## 認証

-  QueuedInterceptorを使ったトークンリフレッシュ
	- トークン失効時にリフレッシュを連打させないためのリクエストの排他制御が必要
	- [【Flutter】DioのQueuedInterceptorでアクセストークン再取得時にデッドロックが発生する落とし穴](https://qiita.com/myzw1mt3/items/d816ad211fadd34b8a25)

### 要件
- 都プラスの新規登録、ログイン、認証管理（アクセストークン、リフレッシュトークン）ができる
- Kintetsu-IDのログイン、認証管理（アクセストークン、リフレッシュトークン）ができる
- 認証コード（OTP）が送信できる
- アカウント連携
	- 都プラスのアカウントにログインしている状態からKintetsu-IDに連携できる
	- Kintetsu-IDのアカウントにログインしている状態から都プラスに連携できる

### 設計
- AuthViewModel
	- トークンローテーション処理？
- authRepositoryProvider - 認証系のリクエスト処理 / データ管理
- authRepository
	- 都プラス、近鉄IDの管理
	- 都プラス、近鉄IDの連携状態
	- アクセストークンとかリフレッシュトークン
- AuthStateProvider - 現在の認証状態の管理
- AuthApiClient / AuthTokenStorage


### Triplaカスタム認証

```
[POST] https://stg-api-point-exif.resort-cloud.com/soap_service/single_sign_on/action
```

```
<?xml version=“1.0” encoding=“utf-8"?>
	<soap:Envelope xmlns:xsi=http://www.w3.org/2001/XMLSchema-instance xmlns:xsd=http://www.w3.org/2001/XMLSchema xmlns:soap=http://www.w3.org/2003/05/soap-envelope>
	<soap:Body>
		<GetUserInformation xmlns=https://www.stg.miyakohotels.jp/service/SingleSignOn/>
			<key>{{client_token}}</key>
			<ip>192.168.0.1</ip>
		</GetUserInformation>
	</soap:Body>
</soap:Envelope>
```
